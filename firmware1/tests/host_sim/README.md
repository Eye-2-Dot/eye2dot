# host_sim — 보드 없이 PC 에서 돌려 보는 모의 시험 (ATmega 쪽)

`mega/src` 의 실제 코드(main·job·link·button·console·punch·solenoid·stepper)를 **고치지 않고 그대로**
PC 의 g++ 로 컴파일해서 "가짜 기계"에 연결한다. 보드·모터가 없어도 타각 순서가 맞는지 몇 초 만에 확인할 수 있다.

```bash
cd firmware1/tests/host_sim
bash run.sh          # g++ 만 있으면 된다 (윈도우는 WSL, 또는 Git Bash + MinGW)
```

마지막 줄에 `전체 결과: 모두 통과` 가 나오면 된다. 코드를 고친 뒤 올리기 전에 한 번 돌려 볼 것.

## 무엇을 흉내 내나

| 파일 | 하는 일 |
|---|---|
| `mock/Arduino.h` | 가짜 Arduino. `micros()`·`delay()` 를 부를 때마다 가짜 시계가 간다 (진짜로 기다리지 않음) |
| `sim_machine.cpp` | 가짜 기계. ULN2003 의 IN1~IN4 가 켜지는 순서를 읽어 헤드·랙 위치를 계산하고, 그 위치로 원점 스위치(D34)의 눌림을 정한다. 솔레노이드(PORTA)가 켜질 때마다 "그때 헤드가 어디 있었나"를 적는다. 소리(`speech.cpp`)는 AVR 타이머를 직접 써서 빈 함수로 바꿨다 |
| `sim_main.cpp` | 시나리오. ESP32 가 보내는 것과 같은 점자 프레임을 Serial1 로 넣고 → 출력 버튼(D32)을 누르고 → 결과를 확인한다 |
| `run.sh` | 컴파일하고 시나리오를 차례로 돌린다 |

## 시나리오

| 이름 | 내용 | 확인하는 것 |
|---|---|---|
| `label` | 15칸 작업, 이어서 빈칸 섞인 6칸 작업 | 칸마다 헤드 자리(오차 0.05mm 안), 순서·값이 받은 그대로, `'D'`, 끝난 뒤 모터·솔레노이드 꺼짐 |
| `wrap` | 같은 작업을 `micros()` 가 0 으로 넘어가는 순간에 | 시간 계산이 넘침에 안전한지 |
| `worst` | 헤드·랙이 반대쪽 끝에서 시작, 15칸 모두 6점 | 가장 오래 걸리는 시간이 ESP32 의 기다림 안에 드는지 |
| `noswitch` / `stuck` | 원점 스위치가 안 눌림 / 계속 눌림 | 아무것도 찍지 않고 `'E'` + 실패음, 모터 꺼짐 |
| `badjob` | 16칸, 두 줄, 빈칸뿐인 줄 | 카드에 안 들어가면 움직이지 않고 `'E'` |
| `console` | USB 명령 `S H G > < Z F , . B M T ?` | 명령마다 헤드·랙이 간 자리 |
| `stopbtn` / `stopusb` | 타각 도중 버튼을 뗐다가 다시 누름 / USB 로 글자를 보냄 | 0.1초 안에 멈추고 `'E'`, 코일·솔레노이드 꺼짐, 다음 작업은 정상 |
| (homeleft) `label` | `HEAD_HOME_AT_RIGHT = false` 로 바꿔 컴파일 | 첫 칸을 가장 먼 자리에 찍고 원점 쪽으로 진행 |
| (sensor) `label`·`nocard` | `CARD_SENSOR_INSTALLED = true` 로 바꿔 컴파일 | 카드가 안 보이면 랙을 되돌리고 `'E'` |

## 이 시험이 알려 주지 못하는 것

- **실제 보드에서 컴파일되는지** — PC 의 g++ 와 보드용 avr-gcc 는 다르다. `pio run` 으로 따로 확인할 것.
- 모터가 힘이 모자라 스텝을 놓치는지, 벨트가 늘어지는지, 솔레노이드 힘이 충분한지 같은 **실물의 문제**.
- ATmega 의 실제 계산 속도. 스텝 하나에 150µs 가 든다고 가정했을 뿐이다.
- 모터가 실제로 그 속도를 따라오는지. 가짜 모터는 스텝을 놓치지 않는다.
- 소리 재생과 타이머 (빈 함수로 바꿨다).
